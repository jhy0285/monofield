# 작업에 맞는 검사와 브라우저 검토 추천

**변경사항 → 변경 검증 → 관련 검사 추천**에서 바꾼 내용을 입력합니다.
**프로젝트 기본 검사 추천**은 발견한 기본 검사만 제시하며 모델을 호출하지 않습니다.
**설정한 판단 모델에 요청**은 선택 기능으로, 설정한 TypeSafe JEV 또는 로컬 호환 서버를 사용합니다.

추천을 적용하면 기존 선택을 보존하고 추천 검사를 앞에 추가합니다.
실제 명령·스크립트를 확인하고 **선택한 검사 실행**을 누르기 전에는 명령이 실행되지 않습니다.
현재 선택한 모듈의 지원 검사만 후보로 사용하며, 새 shell 명령이나 실행 인수를 모델이 만들 수 없습니다.
추천은 검사 범위의 충분함이나 코드의 정답을 증명하지 않습니다.
[실제 검증 기록의 의미](change-verification.md)를 함께 확인하세요.

## JEV 예시에서 가져온 구조

[공식 함수 호출 예시](https://docs.typesafe.ai/cookbooks/function_calling)의 제한된 후보 선택과
[fan-out 예시](https://docs.typesafe.ai/patterns/fan-out)의 독립 질문 일괄 처리를 적용했습니다.
후보마다 관련성을 확인하고, 같은 요청에서 우선 검사를 고릅니다.
watch·자동 수정 스크립트는 모델 후보에서 제외하며 수동 선택만 허용합니다.
최대 여섯 후보와 NONE을 사용하며 선택 확률 0.8 이상, 차순위와 차이 0.5 이상,
해당 검사의 관련성 0.8 이상일 때만 모델 추천을 채택합니다.
이 수치는 보수적인 휴리스틱이며 Laya나 다른 모델에 대해 보정된 신뢰도 기준이 아닙니다.
NONE이나 불확실한 답은 추천을 보류합니다. 모든 실제 검사는 계속 직접 선택할 수 있습니다.

400자 초과 요청·여섯 개 초과 후보·확인 불가능한 소스에는 모델을 호출하지 않습니다.
모델에는 입력한 짧은 요청과 검사 이름·종류·출처만 보냅니다.
소스 파일 내용·명령 스크립트·로그·DB 데이터는 보내지 않습니다.
모델 설정 읽기부터 응답 처리까지 2초 제한이며, 실패·시간 초과에는 프로젝트 기본 검사로 돌아갑니다.
소스 수집 시간은 이 모델 제한에 포함되지 않고 전체 소요 시간에 포함되어 표시됩니다.
현재 작업 트리의 Git-visible 소스를 수집하는 비용은 큰 저장소에서 늘어날 수 있습니다.
입력·열기·추천 적용·실행에는 자동 모델 호출이 없습니다. 실제 평가 시 보고된 토큰만 표시합니다.

## 변경된 코드에 오래된 추천 적용 방지

추천은 Git-visible 소스 지문과 정확한 검사 목록·명령·인수·스크립트에 묶입니다.
추천 중 코드나 목록이 바뀌면 HTTP 409를 반환합니다. 모델 실패 뒤에도 같은 확인을 수행합니다.
추천을 적용하고 나서 코드가 바뀌면 실행 직전에 409로 거절하며 명령을 시작하지 않습니다.
수동으로 선택을 바꾸면 추천 연결을 해제하고 현재 발견한 명령을 실행하는 기존 흐름을 사용합니다.
Git-visible 범위와 제외 항목은 [변경 검증 문서](change-verification.md#기록의-의미와-한계)를 따릅니다.

## 디자인 검토

화면·버튼·CSS·반응형·접근성 등의 요청에는 브라우저 동작, 키보드 조작,
좁고 넓은 화면, 대비 확인 목록도 제시합니다. 이 목록은 요청의 한영 키워드에서 나온
검토 템플릿입니다. 모델이 화면을 관찰했다는 뜻이 아니며 자동 검사 통과로 대체하지 않습니다.
**브라우저 검토 요청 작성**은 원래 요청과 확인 목록을 현재 에이전트 입력란에 넣습니다.
사용자가 검토하고 보내기 전에는 에이전트가 실행되지 않습니다.

## CLI

UI와 같은 API를 호출합니다. 기본은 rules이고 모델 평가는 명시적으로 선택합니다.

```bash
monofield verify suggest --project <id> --prompt-file <path|-> --mode rules --json
monofield verify suggest --project <id> --prompt-file <path|-> --mode model --json
monofield verify run --project <id> --checks <registered-ids> --advice-snapshot <snapshotSha256> --wait --json
```

추천 자체는 명령을 실행하지 않습니다. 출력에는 후보 ID, 추천 ID, 소스 지문,
보류·실패 이유, 수동 확인 목록, 전체 소요 시간, 평가 시도 수, 제공자 보고 토큰이 포함됩니다.
사용량이 확인되지 않으면 null이며 캐시 토큰 수를 추정하지 않습니다.
API는 POST /api/projects/:id/development/verification/advice입니다.
검사 기록은 기존 daemon [데이터 루트 계약](../AGENTS.md#daemon-data-directory-contract)을 따릅니다.
추천은 파일이나 DB에 자동 저장하지 않습니다.
