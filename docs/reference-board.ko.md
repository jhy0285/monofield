# 레퍼런스 보드: 마음에 든 화면의 패턴을 프로젝트에 넣기

다른 사이트에서 좋은 화면을 보면 MonoField 안에서 바로 담아 두었다가, 지금 만드는 프로젝트에 그 **구조·흐름·필드 구성**을 적용하도록 AI에게 부탁할 수 있습니다. 문구·이미지·로고·브랜드 색은 가져오지 않습니다.

## 1. 담기

1. 작업공간의 **+ (새 탭) → 새 브라우저**로 내장 브라우저를 엽니다.
2. 참고할 사이트를 열고, 주소창 오른쪽의 **책갈피 버튼(레퍼런스로 담기)**을 누릅니다.
3. 메모(무엇이 좋았는지)와 **가져올 것**(화면 구조·흐름·필드 구성·상호작용)을 고르고 **담기**를 누릅니다.

담기는 것:

| 항목 | 내용 |
| --- | --- |
| 주소 | 로그인 정보와 `token`, `session`, `key` 같은 이름의 쿼리 값은 지웁니다. |
| 화면 캡처 | 지금 보이는 영역의 PNG. 데스크톱 앱에서만 찍힙니다. |
| 구조 요약 | 큰 영역 순서(header, nav, main…), 제목 단계별 개수, 입력 필드의 종류·라벨·필수 여부, 표의 열 이름과 행 수, 링크·버튼 개수 |
| 메모 | 직접 쓴 내용 |

담지 않는 것: 본문 문구, 이미지·링크 주소, 색, 글꼴.

로그인한 화면은 캡처에 개인 정보가 찍힐 수 있으니 확인하고 담으세요. MonoField는 로그인이나 봇 차단을 대신 통과하지 않습니다.

> 웹 브라우저로 MonoField를 쓸 때는 대부분의 외부 사이트가 내장 브라우저 안에서 열리지 않고, 캡처와 구조 요약도 받을 수 없습니다. 이 경우 주소와 메모만 담깁니다.

## 2. 모아 보기

새 브라우저 탭의 시작 화면(레퍼런스 보드) 맨 위 **담은 레퍼런스**에 카드로 쌓입니다. 카드에서 열기, 메모 수정, 삭제를 할 수 있습니다.

파일은 프로젝트의 `references/` 폴더에 있습니다(`board.json`과 캡처 이미지). 이 폴더에는 자체 `.gitignore`가 있어서 코드 저장소의 변경사항에 섞이지 않습니다. 보드도 함께 커밋하려면 `references/.gitignore`를 지우세요.

## 3. 프로젝트에 넣기

1. 카드의 체크박스로 하나 이상 고르고 **선택한 n개 프로젝트에 넣기**를 누릅니다.
2. **넣을 위치**(프로젝트 파일 경로를 고르거나 화면 이름을 직접 입력)와 **요청**을 적습니다.
3. **입력창에 넣기**를 누르면 채팅 입력창에 부탁문이 붙습니다. 확인하고 보냅니다.

부탁문에는 다음이 들어갑니다.

- 요청과 넣을 위치
- 규칙: 이 프로젝트의 코드·컴포넌트·스타일로 패턴만 다시 만들 것, 문구·이미지·아이콘·로고·브랜드 색·글꼴을 복사하거나 원래 사이트에서 불러오지 말 것, 로그인·봇 차단을 우회하지 말 것
- 레퍼런스마다 주소, 메모, 가져올 것, 캡처 경로(파일이 담을 때와 같은지 SHA-256으로 확인한 결과), 구조 요약

## 4. REA로 흐름 기록 (필요할 때만)

담기는 한 순간의 화면입니다. 버튼을 눌렀을 때 무엇이 바뀌는지, 어떤 API를 부르는지가 중요하면 카드의 **REA로 흐름 기록**을 누릅니다.

1. 단계를 적습니다: 버튼·링크·탭 누르기(보이는 이름), 입력하기(칸 이름 + 공개 값), 글자가 보일 때까지 기다리기, 잠시 기다리기. 최대 12단계입니다.
   단계가 없으면 페이지를 열고 안정된 상태만 기록합니다.
2. **기록 시작**을 누르면 MonoField에 들어 있는 REA가 Chrome·Edge·Chromium을 **새 임시 프로필**로 열어 단계를 실행합니다(최대 2분).
   브라우저를 못 찾으면 "브라우저 직접 지정"에 실행 파일의 전체 경로를 넣습니다.
3. 결과로 단계별 완료·실패, 호출한 API(경로의 번호는 `{id}`로 일반화), 마지막 화면이 카드에 붙습니다. **REA 스튜디오로 열기**를 누르면 단계별 화면과
   요청·응답 본문을 볼 수 있습니다. 파일은 `references/<id>.flow.json`(REA 증거)과 `references/<id>.flow.png`(마지막 화면)입니다.
4. 이후 **프로젝트에 넣기** 부탁문에 흐름 요약(단계, API, 마지막 화면 경로)이 함께 들어갑니다.

지키는 것:

- 새 임시 프로필로 열기 때문에 로그인한 화면은 기록되지 않습니다. 로그인·봇 차단을 우회하지 않습니다.
- 비밀번호·인증번호·카드번호·주민번호 같은 칸에는 입력 단계를 만들 수 없습니다. 주문·결제·전송 버튼은 단계에 넣지 마세요.
- 입력하는 값은 공개해도 되는 값만 쓰세요. 증거 파일에 그대로 남습니다.

단계로 표현하기 어려운 흐름(로그인 뒤 화면, 긴 마법사 등)은 **AI에게 맡기기**를 누르면, 같은 규칙을 담은 기록 요청이 입력창에 들어갑니다. AI가 REA 도구로
기록해 `references/<id>.flow.json`에 저장하도록 부탁하는 문장입니다.

## 5. 우리 화면과 비교 (적용한 뒤)

레퍼런스의 흐름을 기록한 카드에는 **우리 화면과 비교**가 생깁니다. 레퍼런스를 적용해 우리 화면을 만든 뒤 눌러 보세요.

1. **우리 화면 주소**를 넣습니다. 보통 실행 중인 우리 앱 주소입니다(예: `http://localhost:8080/orders`).
2. 레퍼런스를 기록한 단계가 미리 채워져 있습니다. 우리 화면의 버튼·칸 이름이 다르면 고칩니다.
3. **비교 시작**을 누르면 내장 REA가 우리 화면을 같은 단계로 기록하고, 단계마다 레퍼런스와 나란히 비교합니다.

비교하는 것은 **패턴**입니다.

| 항목 | 뜻 |
| --- | --- |
| 성공 여부 | 그 단계를 우리 화면에서도 할 수 있었는지(버튼을 찾았는지, 글자가 나타났는지) |
| 페이지 이동 | 그 단계에서 다른 페이지로 넘어갔는지 |
| 서버 요청 | 그 단계에서 부른 API의 종류와 결과 등급(`GET 2xx`, `POST 4xx` 등). 주소는 비교하지 않습니다 |
| 화면 요소 | 그 단계 뒤 화면에 있는 요소의 종류(표, 목록, 입력칸, 대화상자 등). 이름·문구는 비교하지 않습니다 |

문구·주소·디자인은 원래 달라야 하므로 비교하지 않습니다.

결과 표에서 "다름"이 있으면 **차이를 입력창에 넣기**를 누르세요. 다른 단계와 양쪽 기록 파일이 담긴 부탁문이 입력창에 들어가고, AI는 우리 코드와 문구로
그 단계를 레퍼런스처럼 동작하게 고칩니다. 고친 뒤 다시 비교하면 됩니다. 우리 화면 기록은 `references/<id>.remake.flow.json`에 저장되고 **우리 화면 기록 열기**로
REA 스튜디오에서 볼 수 있습니다. 레퍼런스 흐름을 다시 기록하면 이전 비교는 지워집니다.

## CLI

화면과 같은 API(`/api/projects/:id/references`)를 씁니다.

```sh
monofield refs list    --project <id> [--json]
monofield refs add     --project <id> --url https://example.com/join --note "2단계 가입" --take flow,fields [--screenshot shot.png]
monofield refs note    --project <id> --id <ref-id> --note "버튼 배치가 좋음"
monofield refs remove  --project <id> --id <ref-id>
monofield refs apply   --project <id> --id <ref-id> [--id <ref-id>...] --target src/pages/Join.tsx --request "가입을 두 단계로"
monofield refs apply   --project <id> --id <ref-id> --prompt-file - < request.txt
monofield refs record  --project <id> --id <ref-id> --fill "주문번호=1001" --click 조회 --wait-text "조회 결과" [--browser <path>]
monofield refs record  --project <id> --id <ref-id> --click 다음 --for-agent     # 기록 대신 AI용 요청문 출력
monofield refs compare --project <id> --id <ref-id> --url http://localhost:8080/orders [단계 플래그] [--browser <path>]
monofield refs compare --project <id> --id <ref-id> --url http://localhost:8080/orders --block   # 차이를 AI용 부탁문으로 출력
```

`record`는 단계 플래그를 적은 순서대로 실행합니다(`--click`, `--click-link`, `--fill "칸=값"`, `--wait-text`, `--wait <ms>`, `--steps-file <json>`).
실패한 단계가 있으면 종료 코드 1로 끝납니다. `compare`는 단계 플래그를 주지 않으면 레퍼런스를 기록한 단계를 그대로 쓰고, 레퍼런스와 다른 단계가
있으면 종료 코드 1로 끝납니다. 그래서 AI가 고치고 다시 비교하는 반복에 그대로 쓸 수 있습니다.

`add`는 화면을 직접 캡처하지 않습니다. 캡처가 필요하면 `--screenshot`으로 이미지 파일(PNG·JPEG)을 넘기거나, `record`로 흐름을 기록하세요(기록한
마지막 화면이 카드 그림이 됩니다).

## 한계

- 비교는 기록한 한 번의 실행을 본 것입니다. 모든 경우에 같게 동작한다는 증명이 아닙니다.
- 버튼에 접근 가능한 이름이 없으면(아이콘만 있는 버튼 등) 단계로 찾을 수 없습니다. 그런 흐름은 "AI에게 맡기기"를 쓰세요.
