# 토큰 절약 기준

MonoField는 일반 Codex 작업에서 앱의 반복 안내문을 제거하고, 문서·이미지 작업은 필요한 변경과 근거만 모델에 보내는 방향으로 동작합니다. 여기서 문자 수는 프롬프트 크기이고, 제공자가 청구하는 토큰 수나 비용과 다릅니다.

## 일반 Codex 작업

네이티브 Codex CLI를 사용하는 **Ask / 개발 채팅**에서 별도 스킬·디자인 시스템·메모리·사용자 지침·연결 DB·브라우저·리서치 등 추가 맥락이 없으면 사용자 요청을 그대로 CLI에 전달합니다. 첫 턴과 같은 맥락의 세션 재개 턴 모두 앱이 더하는 프롬프트는 0자입니다. Codex 자체 시스템 지침, 프로젝트의 AGENTS.md, 도구, 권한 경계는 그대로 사용합니다.

작업 폴더는 Codex의 네이티브 CLI 인자로 전달합니다. 매 턴 루트 파일 목록과 사용하지 않는 앱 도구 설명을 반복해서 보내지 않습니다. 제목은 첫 요청에서 로컬로 만들므로 제목 생성용 모델 작업이 없습니다. 네이티브 세션 재개와 기존 안정된 지침 해시 캐시를 계속 사용합니다. 새 모델 세션에 이전 대화가 필요한 경우에는 대화를 보존합니다.

선택한 파일·스킬·DB·메모리·사용자 지침은 필요한 추가 맥락이므로 보존합니다. 변경된 지침을 전달하거나 이전 선택을 해제한 재개 턴에는 짧은 맥락 갱신 안내가 붙습니다. 메모리 본문의 사실·제약을 자르거나 모델로 다시 요약하지 않고, 채팅과 명세서 안내에 불필요한 장문의 제작 절차 설명만 줄입니다.

## 문서와 이미지

- [DB 스키마 감시와 연결 영향 분석](database-schema-watch.md)은 로컬 메타데이터 비교와 문서 연결 탐색으로 처리합니다. 감시·확인·그래프 분석은 모델을 호출하지 않습니다. 아래 36턴 토큰 비교는 이 후속 기능 개발 전의 일반 Codex 작업 측정입니다.
- 인터페이스 명세서 갱신은 변경분 JSON을 우선 사용합니다. 원본 해시 검사·병합·스키마 검증·화면 비교는 로컬 daemon이 처리합니다. 변경하지 않는 인터페이스를 AI가 다시 출력할 필요가 없습니다. 검증 CLI도 기본적으로 전체 문서를 반환하지 않습니다.
- Git 영향 분석의 AI 요청에는 긴 목록의 일부와 전체 개수를 담습니다. 전체 사실은 보고서에 유지하며 필요할 때 CLI로 가져옵니다. 큰 원본 문서는 로컬 도구로 관련 항목만 추출합니다.
- 구조화 명세서 작업에는 무관한 이미지·영상·오디오 제작 안내를 넣지 않습니다. 해당 미디어 작업의 계약은 유지합니다.
- 이미지 입력을 지원하는 API 제공자 경로에서는 한 요청 내에 같은 이미지 바이트를 한 번만 첨부합니다. 반복 첨부는 앞선 이미지 참조가 됩니다. 서로 다른 이미지는 보존하고, 읽기 캐시는 프로젝트 간이나 요청 간에 공유하지 않습니다.

## 실행별 확인

```bash
monofield run info <run-id> --json
```

UI와 같은 daemon 실행 정보에서 `promptContext`를 조회합니다.

| 필드 | 의미 |
| --- | --- |
| `profile` | 네이티브 Codex 채팅인지, 기타 지원 워크플로인지 |
| `requestCharacters` | 모델에 전달할 사용자 요청 부분의 문자 수 |
| `composedCharacters` | 앱이 조합한 전체 요청의 문자 수 |
| `addedCharacters` | 앱이 추가한 안내·첨부·맥락의 문자 수 |
| `stableCharactersSkipped` | 재개 시 생략한 안정된 맥락 해시 입력의 크기. 내부 폴더 정보도 포함되므로 실제 절감 토큰 수가 아님 |

제공자 응답의 실제 사용량은 별도로 처리합니다. OpenAI Responses의 `input_tokens_details.cached_tokens`도 인식하며 입력 토큰의 부분집합으로 계산합니다. 캐시 토큰을 입력에 다시 더하거나 무료라고 계산하지 않습니다.

## 검증한 범위

2026-10-01의 로컬 검사에서 일반 Codex 첫 턴·재개 턴의 CLI 표준입력이 사용자 요청과 정확히 같음을 확인했습니다. daemon prompt composer의 같은 조건은 기존 3,194자에서 0자가 됐습니다. 200개 인터페이스·2,000개 필드의 합성 문서에서 필드 하나의 타입과 검토 상태를 바꾸는 제안은 전체 JSON 1,049,963자 대신 변경분 504자였으며, 합친 문서가 유효하고 다른 인터페이스가 유지됐습니다. 이는 해당 사례의 출력 크기 비교이며 전체 업무 비용 절감률이 아닙니다.

같은 Codex 버전·모델·추론 설정·폴더·대화·선택 맥락으로 실제 사용량을 비교해야 총비용을 판단할 수 있습니다. 모델의 추론과 도구 출력, 추가 선택 맥락까지 포함한 모든 작업의 토큰이 직접 Codex보다 적다는 보장은 아직 없습니다. 회귀 테스트는 일반 작업의 앱 추가 프롬프트 0자, 선택 맥락 보존, 반복 이미지 제거, 변경분 검증을 지속해서 검사합니다.

## 실제 비교 실행

유지보수하는 측정 도구는 `e2e/scripts/token-benchmark.ts`입니다. 기본 명령은 계획만 출력합니다.

```bash
node --import tsx e2e/scripts/token-benchmark.ts
node --import tsx e2e/scripts/token-benchmark.ts --check
node --import tsx e2e/scripts/token-benchmark.ts --run
```

`--check`는 직접 CLI와 MonoField HTTP 경로에서 같은 `OK` 요청을 각각 한 번 실행합니다. 명시적 네트워크 정책 거부가 발생하면 다음 호출을 중단합니다. `--run`은 직접 CLI 연결 확인 한 턴을 거친 뒤, 3쌍의 첫 요청·세션 재개 기억 확인·짧은 코드 검토를 비교합니다(비교 18턴, 연결 확인 포함 19턴). 기본 모델은 `gpt-6.1-sol`, 추론 수준은 `low`입니다. 현재 환경에서 제공자가 지원하는 모델인지 먼저 확인합니다. `MONOFIELD_BENCH_MODEL`, `MONOFIELD_BENCH_PAIRS`, `MONOFIELD_BENCH_OUTPUT`으로 설정할 수 있습니다. `MONOFIELD_BENCH_FIXTURE`로 기존 측정 폴더를 재사용할 수 있으며, 기존 `totals.ts` 내용이 예상 fixture와 다르면 덮어쓰지 않고 중단합니다.

양쪽에 같은 Codex CLI·인증·작업 폴더·workspace-write 권한·외부 플러그인 비활성화 조건을 사용합니다. 외부 플러그인을 켠 기본 CLI와의 비교는 아닙니다. MonoField 런타임은 tools-dev로 시작하며, 데이터 격리는 루트 [AGENTS.md의 Daemon data directory contract](../AGENTS.md)를 따릅니다. 측정 도구가 시작한 런타임만 종료합니다.

결과 경로는 명령 출력에 표시됩니다. `result.json`과 원시 CLI JSONL·stderr·MonoField SSE·실행 레코드를 보존합니다. 입력·캐시 입력·비캐시 입력·출력을 따로 기록하고, 재개 턴에서는 동일 세션의 누적 사용량 차이를 계산합니다. 누락된 사용량을 0으로 채우지 않습니다. 앱이 추가한 맥락도 기록하므로 성공한 비교에서 추가 토큰을 조사할 수 있습니다. 최종 완료된 assistant 메시지가 정답인 완성된 양쪽 쌍만 집계하며 실패 기록은 남깁니다. 진행 안내를 최종 답에 붙여 채점하지 않습니다. 진행 안내까지 포함한 전체 응답 형식 준수율은 별도로 기록합니다. 제공자 캐시는 강제로 초기화하지 않으며 비용을 추정하지 않습니다.

2026-10-01 새 환경에서는 처음에 로그인 상태 표시와 달리 HTTP 401 인증 갱신 실패가 발생했습니다. 기기 인증으로 갱신한 뒤 연결에 성공했습니다. 기존 `gpt-5.4`는 현재 ChatGPT 계정에서 지원되지 않아 제공자 모델 목록에서 확인한 `gpt-6.1-sol / low`로 양쪽을 실행했습니다.

같은 Codex CLI `0.159.0-alpha.3`, 인증, fixture 폴더와 파일, 권한, 지침으로 3쌍을 측정하고 채점 오류를 수정한 후 3쌍을 다시 측정했습니다. 1차의 원시 이벤트를 보존한 채 최종 답 기준으로 재채점했고, 진행 안내가 있었던 경우의 형식 점수도 보존했습니다. 두 차례 모두 각 경로 9/9 최종 정답이며, 합산은 각 경로 18/18입니다. 전체 응답 형식 준수는 직접 CLI 14/18, MonoField 18/18입니다. 이 작은 표본으로 일반 품질 우위를 주장하지 않습니다.

| 두 차례 합산, 비교 36턴 | 직접 Codex | MonoField |
| --- | ---: | ---: |
| 전체 입력 | 340,944 | 340,679 |
| 입력 중 캐시 | 320,512 | 306,304 |
| 비캐시 입력 | 20,432 | 34,375 |
| 출력 | 552 | 439 |

양쪽의 각 작업 첫 모델 호출 입력은 각각 14,114 / 14,148 / 14,192토큰으로 같았습니다. 코드 검토는 파일을 읽은 뒤 두 번째 모델 호출이 있어 전체 입력에 그 호출까지 포함합니다. 완료된 `turn.completed`의 누적 사용량과 MonoField의 재개 턴 차이를 제공자의 rollout `last_token_usage` 합계와 대조해 36턴 전부 일치함을 확인했습니다. 모델 기본 지침, developer 메시지와 실행 조건의 해시·값도 두 경로가 같았습니다. MonoField의 비교 요청 18개 모두 `addedCharacters: 0`이었습니다.

전체 입력은 265토큰(0.078%) 적었지만, MonoField의 비캐시 입력은 13,943토큰(68.24%) 많았습니다. 캐시 입력이 14,208토큰 적었으며, 캐시는 전체 입력의 일부입니다. 제공자 캐시 적중 차이의 내부 원인은 이 측정에서 확인할 수 없습니다. 입력 크기나 총 토큰의 작은 차이를 비용 절감으로 해석하지 않습니다. 각 작업 첫 호출 이후의 차이는 모델의 진행 안내·추론·도구 호출로 달라진 후속 입력과 출력에 포함돼 있습니다.

결과의 범위는 별도 선택 맥락이 없는 첫 요청·기억 확인·짧은 코드 검토입니다. 문서·화면·DB·대규모 프로젝트 업무의 품질과 비용을 입증한 결과는 아닙니다. 제공자 캐시를 강제 초기화하거나 같은 상태로 보장할 수 없으므로, 모든 업무에서 직접 Codex보다 적은 토큰이나 비용을 보장하지 않습니다.
