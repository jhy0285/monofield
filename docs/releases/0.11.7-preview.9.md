# MonoField 0.11.7-preview.9 — 바뀐 API만 정확히, Spring 스캐너 보강

Codex·Claude Code로 SI 산출물까지 끝내는 MonoField 개발 프리뷰입니다. Windows x64에서 안정 버전과 별도로 설치됩니다. 0.11.7-preview.8의 기능은 그대로이고 다음이 바뀌었습니다.

- **Git 변경 분석이 바뀐 API만 표시합니다**: 스캐너로 만든 Spring 명세서라면 기준 시점의 코드와 지금 코드를 같은 스캐너로 다시 읽어 비교합니다. 계약이 실제로 바뀐 인터페이스, 호출자 호환성(호환성 깨짐 · 확인 필요 · 추가 변경), 명세서에 아직 없는 새 인터페이스를 AI 없이 PC 안에서 보여 줍니다. 가상 교통 결제 시스템(API 68개) 실험에서 이전 방식은 60개를 표시하고 그중 26개가 실제로는 바뀌지 않았는데, 이제 바뀐 34개만 표시합니다. 다시 읽을 수 없으면(Python 없음, 직접 만든 명세서 등) 이전처럼 파일 기준으로 표시하고 이유를 적습니다.
- **명세서가 읽은 커밋을 기록합니다**: Java·XML 파일이 모두 커밋된 상태에서 명세서를 만들면 그 커밋을 남겨, 코드 변경을 먼저 커밋해도 변경 분석의 기준점이 유지됩니다.
- **Spring 스캐너 보강**: Java `record` DTO, 상수로 만든 경로(`ApiPaths.V1 + "/x"`), `@JsonProperty`·`@JsonIgnore`·`@JsonNaming`, `@RequestHeader`와 `@PathVariable`·`@RequestParam`의 이름·필수 여부·타입, `Map` 응답의 키, `@Size`·`@Length` 최대 길이, 경로 별칭, 추상 컨트롤러, 테스트 소스 제외. 감사 필드 규칙을 낱말 단위로 좁히고 `--include-audit-fields` 옵션을 더했습니다.
- **XML 보안 설정 읽기**: 전자정부프레임워크식 `context-security.xml`의 `<http>`, `<intercept-url>`, `security="none"`으로 인증 여부를 정하고 XML 파일과 줄을 근거로 남깁니다.
- **새 사용 가이드**: 개발자는 예제로 명세서 만들기부터 변경 분석·반영까지 따라 하고, PM·팀장은 Excel과 변경 분석 결과를 읽는 법을 봅니다. 어떤 단계가 코드를 AI 회사로 보내는지, 외부 AI 없이 쓰는 방법도 적었습니다. [사용 가이드](https://monofield.vercel.app/guide)

실험 결과(가상 시스템, API 68개): 경로 68/68, 인증 68/68, 바뀐 항목 152/152, 영향받은 API 34/34(불필요한 표시 0), 명세서 한 번 0.3초. 열거값 추가·기본값 변경·권한 범위 변경은 아직 찾지 못하고, Kotlin은 읽지 않습니다. [실험 방법과 전체 결과](https://github.com/jhy0285/monofield/blob/main/docs/testing/abt-scanner-vs-claude-code-2026-11-09.md)

직접 다운로드 설치본은 **서명되지 않았습니다**. `SHA256SUMS.txt`로 다운로드를 확인하세요. 이 릴리스는 preview이며 안정 버전의 latest 다운로드를 바꾸지 않습니다. Codex 또는 Claude Code CLI는 별도로 설치·로그인해야 하며, 에이전트가 사용하는 모델 제공업체의 이용 조건과 요금이 그대로 적용됩니다. 정밀 변경 분석에는 Python 3이 필요합니다. 프리뷰 업데이트는 이 페이지의 설치본으로 진행하세요.
