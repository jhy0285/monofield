# MonoField 0.11.7-preview.12 — AI에게 맡긴 일을 한곳에서 보고 검사합니다

Codex·Claude Code로 SI 산출물까지 끝내는 MonoField 개발 프리뷰입니다. Windows x64에서 안정 버전과 별도로 설치됩니다. 0.11.7-preview.11의 기능은 그대로이고 다음이 추가되었습니다.

- **작업 큐**: 왼쪽 메뉴에 새 화면이 생겼습니다. AI에게 보낸 요청마다 번호가 붙은 카드가 실행 중, 답변 필요, 완료, 실패·취소 칸에 놓이고, 지금 동시에 도는 실행 수가 보입니다. 카드를 누르면 그 대화로 갑니다.
- **실행 뒤 자동 검사**: 프로젝트 폴더가 Git 저장소면 실행이 끝날 때 그 실행이 바꾼 것만 골라 검사합니다. 실행 전에 직접 고쳐 둔 내용은 빠집니다. Spring 코드가 바뀌었으면 호출하는 쪽이 깨지는지 비교해 카드에 "API 호환성 깨짐 n", "API 추가 변경 n" 같은 배지로 보여 주고, 배지를 누르면 바뀐 필드, 건드린 API·화면·테이블·클래스, 바뀐 파일이 나옵니다. 사용자의 파일, 스테이징, 브랜치는 건드리지 않습니다.
- **결과물 보관과 되돌리기**: 실행마다 만든 문서·시트·슬라이드·이미지·데이터 파일을 사본으로 보관하고 같은 파일은 버전으로 묶습니다. 요청·AI·형식으로 찾고, 미리보기·크게 보기·내려받기, 예전 버전으로 되돌리기가 됩니다. 소스 코드와 숨김 파일은 보관하지 않습니다.
- **작업 기록과 토큰**: 요청마다 사용한 AI, 결과, 각 도구가 보고한 토큰을 남기고 기간·AI·프로젝트별 합계를 보여 줍니다.
- **AI 없이 명세서, PR에서 API 검사**: `monofield docs scan`이 코드에서 명세서와 Excel을 바로 만들고, `monofield docs check --base <기준 커밋>`은 API가 깨지면 실패해서 PR 검사에 쓸 수 있습니다.
- **고친 것**: 인터페이스 이름에 `:` 같은 문자가 있으면 Excel 내보내기가 멈추던 문제를 고쳤습니다. 이제 전자정부 공통컴포넌트 API 1,206개가 Excel로 나옵니다. 같은 주소를 `params` 조건으로 나눈 Spring 핸들러는 별개 API로 읽습니다.

터미널에서는 `monofield queue`, `monofield queue check <실행 번호>`, `monofield outputs`, `monofield usage`로 같은 내용을 봅니다. API 비교는 Spring(Java·Kotlin)에서만 하고 Python 3가 필요합니다. 건드린 항목은 Java, Vue, React, JavaScript, TypeScript 파일을 읽고 Python은 아직 읽지 않습니다. 작업 큐와 자동 검사는 실제 Codex CLI 대신 같은 출력 형식의 대역 프로그램으로 시험했습니다.

알려진 문제: 설치본에서는 코드 지도(온톨로지) 분석과 Java 소스의 클래스 자동 찾기가 파일을 찾지 못해 실패합니다. 이전 프리뷰부터 있던 문제이며 다음 미리보기에서 고칩니다.

직접 다운로드 설치본은 **서명되지 않았습니다**. `SHA256SUMS.txt`로 다운로드를 확인하세요. 이 릴리스는 preview이며 안정 버전의 latest 다운로드를 바꾸지 않습니다. Codex 또는 Claude Code CLI는 별도로 설치·로그인해야 하며, 에이전트가 사용하는 모델 제공업체의 이용 조건과 요금이 그대로 적용됩니다. 프리뷰 업데이트는 이 페이지의 설치본으로 진행하세요.
