# MonoField 0.11.7-preview.10 — 열거값·기본값·권한 변경까지, 실제 Spring 프로젝트로 검증

Codex·Claude Code로 SI 산출물까지 끝내는 MonoField 개발 프리뷰입니다. Windows x64에서 안정 버전과 별도로 설치됩니다. 0.11.7-preview.9의 기능은 그대로이고 다음이 바뀌었습니다.

- **열거값·기본값·권한 변경을 찾습니다**: 명세서에 필드가 받는 값(열거값), 요청에서 빠졌을 때 쓰는 기본값, API를 부를 수 있는 권한이 들어갑니다. 응답 상태값이 하나 늘면 "확인 필요", 요청에서 받던 값이 빠지면 "호환성 깨짐", 기본값이 바뀌면 "확인 필요", 필요한 권한이 바뀌어 부르던 쪽이 막히면 "호환성 깨짐"으로 나옵니다. Excel 비고 칸, OpenAPI 내보내기, 명세서 편집기에도 함께 보입니다.
- **실제 Spring 프로젝트 두 개로 재고 고쳤습니다**: RealWorld 예제 앱을 공식 OpenAPI 문서와 비교하면 경로 19/19, 로그인 필요 여부 19/19, 요청 필드 37/38을 맞힙니다(preview.9는 경로 0/19). 전자정부 공통컴포넌트(Java 파일 1,103개)에서는 3초에 API 1,206개를 찾고, 실제 커밋 20개를 다시 보면 보고한 변경 36건 중 35건이 실제 diff와 맞고, 1건은 기본값을 메서드 안으로 옮긴 경우라 호출하는 쪽의 동작은 같았습니다. 이 과정에서 이름이 `*Controller`가 아닌 컨트롤러, 정적 import한 HTTP 메서드, `@JsonRootName`, `ResponseEntity<?>` 응답, 한 파일 안의 여러 클래스를 읽게 했고 `int`와 `Integer`를 같은 타입으로 비교합니다.
- **명세서 편집기의 인증 칸**: 문서 공통 인증을 따르는 API에 `undecided` 대신 "Bearer 토큰 (문서 공통)"처럼 읽을 수 있는 이름이 나옵니다.

실험 결과: 가상 교통 결제 시스템(API 68개)에서 열거값·기본값·권한 변경 4/4, 기존 변경 152/152(잘못된 경보 0). 메서드 안에서 정하는 기본값은 읽지 못해 "확인 필요"로 나올 수 있고, Kotlin은 아직 읽지 않습니다.
