# MonoField 처음 시작하기

이 문서를 끝까지 따라 하면 15분 안에 다음 세 가지를 직접 해 봅니다.

1. 예제 Spring 프로젝트에서 **인터페이스 명세서 Excel**을 만듭니다.
2. 코드를 한 군데 고치고, 명세서에서 **바뀐 부분만** 검토해 반영합니다.
3. 같은 명세서를 **OpenAPI 파일**로 내보냅니다.

> 이 문서는 예제로 따라 하는 **15분 튜토리얼**입니다. 결과를 받아 보는 PM·팀장용 설명과 "이 일은 어디서 하지?"는 [사용 가이드](user-guide.ko.md)를 보세요.

> **MonoField는 무엇인가요?**
> 이미 쓰는 Codex나 Claude Code를 내 PC에서 실행해, 코드에서 SI 산출물(인터페이스 명세서, 화면명세서)을 만들고 코드가 바뀔 때 산출물도 맞춰 주는 작업 도구입니다. 명세서의 각 항목에는 근거가 된 파일과 줄이 남습니다.

---

## 0. 준비물

시작하기 전에 아래 다섯 가지를 확인하세요. 명령 프롬프트(또는 PowerShell)에서 "확인 방법"의 명령을 입력해 버전이 나오면 준비된 것입니다.

| 준비물 | 확인 방법 | 없으면 |
| --- | --- | --- |
| Windows 10/11 (64비트) | — | 현재 데스크톱 앱은 Windows만 지원합니다. |
| Codex CLI **또는** Claude Code CLI | `codex --version` 또는 `claude --version` | 각 CLI의 공식 안내대로 설치한 뒤 **로그인까지** 마칩니다. 둘 중 하나면 됩니다. |
| Python 3 | `python --version` | [python.org](https://www.python.org/downloads/)에서 설치합니다. 설치 첫 화면에서 **"Add python.exe to PATH"**를 꼭 체크하세요. 명세서 스캐너가 Python으로 동작합니다. 이 문서는 Python 3.13으로 확인했습니다. |
| Git | `git --version` | [git-scm.com](https://git-scm.com/download/win)에서 설치합니다. 코드 변경을 비교할 때 씁니다. |
| 인터넷 연결 | — | 설치와 AI 호출에 필요합니다. |

> **비용과 보안**: 이 튜토리얼은 채팅으로 Codex·Claude Code에게 명세서와 코드 수정을 시키므로, 그 AI가 코드를 읽고 코드 일부가 해당 회사로 전송됩니다. 요금도 그 계정 기준입니다. 명세서 스캐너, Excel·OpenAPI 내보내기, **Git 변경 분석**은 AI 없이 PC 안에서만 돕니다. 외부 AI가 금지된 현장은 [사용 가이드의 "외부 AI를 쓸 수 없는 현장이라면"](user-guide.ko.md#외부-ai를-쓸-수-없는-현장이라면)를 보세요.

## 1. 설치 (2분)

1. [MonoField 사이트](https://monofield.vercel.app/#preview)에서 **Preview 설치본**을 내려받아 실행합니다.
2. 설치본은 아직 코드 서명이 되어 있지 않아 "Windows의 PC 보호" 창이 뜰 수 있습니다. **추가 정보 → 실행**을 누르면 됩니다. 내려받은 파일이 맞는지 확인하려면 같은 위치의 `SHA256SUMS.txt`와 비교하세요.
3. 프리뷰는 안정 버전과 **따로** 설치됩니다. 안정 버전이 있어도 지워지지 않습니다.

---

## 2. 처음 켰을 때 (3분)

1. **화면 안내가 자동으로 시작됩니다.** 강조된 곳을 따라 눌러 보세요. 나중에 다시 보려면 왼쪽 사이드바 맨 아래의 **?**(도움말) → **가이드 · 소개 영상** → **화면 투어 다시 보기**를 누릅니다. 사이드바가 접혀 있으면 왼쪽 위 **사이드바 펼치기** 버튼으로 엽니다.
2. **AI 연결 확인**: 설정(톱니바퀴) → **실행 모드**에서 **로컬 CLI**를 고르고, 목록에 Codex 또는 Claude Code가 감지되었는지 봅니다. 보이지 않으면 아래 [막혔을 때](#6-막혔을-때)를 보세요. API 키(BYOK)만 연결하면 대화와 문서 생성만 되고, 폴더를 읽고 고치는 명세서 흐름은 쓸 수 없습니다.
3. **실행 권한 확인**: 설정 → **실행 권한**은 처음에 **기본**입니다. 그대로 두세요.

| 단계 | 하는 일 | 언제 쓰나요 |
| --- | --- | --- |
| 읽기 전용 | 파일을 읽고 계획만 세웁니다. 아무것도 바꾸지 않습니다. | 처음 보는 코드에 대해 질문만 할 때 |
| **기본 (권장)** | 작업 폴더 안에서만 파일을 고치고 명령을 실행합니다. | 명세서 생성, 코드 수정 등 거의 모든 작업 |
| 전체 접근 | PC 전체에서 확인 없이 실행하고, Windows에서는 관리자 권한으로 다시 시작합니다. | 빌드 도구가 관리자 권한을 요구할 때만 |

> 명세서를 만들면 프로젝트 안에 파일이 생기므로 **읽기 전용에서는 만들 수 없습니다.** 명세서 작업은 **기본**에서 하세요.

## 3. 예제로 첫 명세서 만들기 (5분)

### 3-1. 예제 프로젝트 준비

1. [예제 프로젝트(legacy-order.zip)](https://monofield.vercel.app/downloads/monofield-sample-legacy-order.zip)를 내려받아 원하는 곳에 압축을 풉니다. 회원 가입·주문 API가 있는 작은 Spring 프로젝트입니다.
2. 압축을 푼 `legacy-order` 폴더에서 명령 프롬프트를 열고 아래 세 줄을 입력합니다. 지금 상태를 Git에 기준점으로 저장해 두는 단계입니다.

   ```bash
   git init
   git add -A
   git commit -m "baseline"
   ```

   `Please tell me who you are` 오류가 나면 [막혔을 때](#6-막혔을-때)를 보세요.

### 3-2. 명세서 만들기

1. MonoField 홈에서 **작업 폴더 선택**을 눌러 `legacy-order` 폴더를 고릅니다.
2. 홈 위쪽에서 **문서/디자인 제작**이 선택되어 있는지 확인하고, 입력창 아래 **결과 형식 선택**에서 **인터페이스 명세서** 카드를 누릅니다. 그다음 입력창에 아래처럼 보냅니다.

   > 선택한 Spring 프로젝트의 Controller를 스캔해서 인터페이스 명세서 Excel을 만들어 줘

3. 채팅에 "간단한 질문 몇 가지 드려도 될까요?"가 뜨고, 오른쪽 **질문** 탭에 선택지가 두 번에 나눠 나타납니다.
   - 첫 번째 **인터페이스 명세서 작성 방식**: **작성 방식** → **코드베이스에서 생성**
   - 두 번째 **인터페이스 명세서 설정**: **한글-영어 매핑 사전** → **사전 업로드** → 예제 폴더의 `docs/term-dictionary.csv`
   - 나머지 항목은 기본값으로 두고 제출합니다.
4. 잠시 기다리면 프로젝트 안에 `…interface-spec.json` 파일이 생기고 미리보기가 열립니다. **내보내기**를 누르면 Excel이 만들어집니다. 표지, 인터페이스 목록, API별 시트가 들어 있습니다.

### 3-3. 이것만은 사람이 확인하세요

자동으로 확정할 수 없는 칸은 비워 두거나 표시해 둡니다. 추측해서 채우지 않습니다.

| 칸 | 왜 확인해야 하나요 |
| --- | --- |
| 인터페이스 ID (예: `IF-ORD-001`) | 코드에 없는 정보라 사람이 정합니다. |
| 업무명 | 메서드 위에 한글 주석(`/** 주문 등록 */`)이 있으면 그 문장을 쓰고, 없으면 확인 대상으로 남습니다. |
| 한글 필드명 | 용어 사전 → 필드의 한글 주석 → 영문 분리 순서로 정합니다. `member Id`처럼 남은 필드는 사전에 추가하세요. |
| 인증 여부 "확인 필요" | Java 보안 설정, XML 보안 설정(`context-security.xml`)과 애너테이션으로 판단합니다. 서블릿 필터, 인터셉터, DB에 저장한 접근 규칙으로만 막는 경우는 읽지 않으므로 직접 확정합니다. |

## 4. 코드를 바꾸고 명세서를 따라가게 하기 (5분)

1. 채팅에 아래처럼 보냅니다.

   > 주문 등록에 배송 요청 사항(deliveryMemo)을 추가하고 주문 취소 API를 만들어 줘

2. 에이전트가 코드를 고치면 **변경사항** 탭에서 바뀐 줄과 빌드 결과를 확인합니다.
3. 명세서 편집기로 돌아가 아래 순서로 누릅니다.
   1. **Git 변경 분석** — AI 없이, 3-1에서 저장한 기준점의 코드와 지금 코드를 스캐너로 다시 읽어 비교합니다. 맨 위에 "기준 시점과 지금의 코드를 스캐너로 다시 읽어 비교했습니다"가 보이고, 요청대로 고쳐졌다면 **영향받은 항목**에 주문 등록 하나, **호출자 호환성**에 "추가 변경", **문서에 없는 새 인터페이스**에 주문 취소 API가 나옵니다.
   2. **AI 갱신 요청 작성** → 전송 — 바뀐 인터페이스에 대해서만 수정안을 만들게 합니다.
   3. **AI 제안 검토** — 바뀐 인터페이스만 보입니다. 에이전트가 요청대로 고쳤다면 주문 등록에 `deliveryMemo`가 추가되고 주문 취소 API가 새로 제안됩니다.
4. **호출자 호환성**(변경 분석 결과와 제안 화면 위쪽에 나옵니다)을 봅니다.
   - **호환성 깨짐**: 기존 호출 쪽이 고장 날 수 있는 변경(필드 삭제, 필수값 추가 등)
   - **확인 필요**: 사람이 판단해야 하는 변경
   - **추가 변경**: 기존 호출에 영향 없는 변경(이번 예제)
5. **검토한 제안 적용** → 저장 → **내보내기**로 새 버전 Excel을 만들고, **OpenAPI 내보내기**로 API 게이트웨이·Mock 서버용 OpenAPI 3.1 파일도 받습니다.

> 제안을 검토하는 사이에 원본 명세서가 바뀌면 적용이 거부됩니다. 다시 **Git 변경 분석**부터 하면 됩니다.
>
> 코드 변경을 먼저 커밋해도 됩니다. 명세서를 만들 때 Java·XML 파일이 모두 커밋되어 있었다면 스캐너가 그 커밋을 기록해 두고 그 커밋과 비교합니다.

## 5. 내 프로젝트에 적용할 때

- **폴더**: Git 저장소의 루트(또는 모듈 폴더)를 작업 폴더로 고릅니다. Git 기록이 없으면 3-1처럼 기준점을 먼저 만드세요.
- **용어 사전부터**: 팀에서 쓰는 이름을 `영문 식별자,한글명` 형식의 CSV로 정리해 두면 한글 필드명이 정확해집니다. 예제의 `docs/term-dictionary.csv`를 틀로 쓰면 됩니다.

  ```csv
  memberId,회원 ID
  orderNo,주문번호
  ```

- **이미 Swagger(OpenAPI) 문서가 있다면**: 입력창에 "이 OpenAPI 파일로 인터페이스 명세서를 만들어 줘"라고 보내고 파일 위치를 알려 주세요. JSON이 가장 확실합니다(springdoc이면 `/v3/api-docs`).
- **전자정부프레임워크(.do)**: Controller·DTO와 XML 보안 설정(`<intercept-url>`)을 읽어 인증 칸을 채웁니다. DB에 저장한 접근 규칙이나 서블릿 필터로만 막는 URL은 "확인 필요"로 남습니다. 정상입니다.
- **화면명세서**: 홈의 **결과 형식 선택** → **화면명세서**에서 화면 캡처를 올리고 마커·Description·Check Point를 편집한 뒤 PPTX로 내보냅니다.
- **처음 한두 주는 모듈 하나만** 이 방식으로 관리해 보세요. 기존 방식과 비교해 갱신 시간이 얼마나 줄었는지, 검토에서 빠진 변경이 있었는지를 보면 계속 쓸지 판단하기 쉽습니다.

## 6. 막혔을 때

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 설치할 때 "Windows의 PC 보호" 창 | 설치본에 아직 코드 서명이 없습니다. | **추가 정보 → 실행**. 필요하면 `SHA256SUMS.txt`로 파일을 확인합니다. |
| 실행 모드 → 로컬 CLI에 Codex/Claude가 안 보임 | CLI가 PATH에 없거나 로그인하지 않았습니다. | 명령 프롬프트에서 `codex --version`(또는 `claude --version`)이 되는지 확인하고, 로그인한 뒤 MonoField를 다시 켭니다. |
| `python`을 찾을 수 없다는 메시지 | Python이 없거나 PATH에 없습니다. | Python을 설치하면서 **Add python.exe to PATH**를 체크합니다. 설치 후 MonoField를 다시 켭니다. |
| "현재 작업 폴더는 Git 저장소가 아닙니다" | Git 기준점이 없습니다. | 3-1의 `git init` 세 줄을 실행합니다. |
| `git commit`에서 `Please tell me who you are` | Git 사용자 정보가 없습니다. | `git config --global user.name "이름"`과 `git config --global user.email "메일"`을 한 번 실행한 뒤 다시 커밋합니다. |
| 한글 필드명이 `member Id`처럼 나옴 | 사전에도 주석에도 없는 이름입니다. | 용어 사전에 추가하고 다시 만듭니다. |
| 인증이 "인증 여부 확인 필요"로 남음 | 근거가 될 Java·XML 보안 설정을 찾지 못했거나 풀 수 없는 규칙입니다(필터, DB 규칙, `hasIpAddress` 등). | 오류가 아닙니다. 검토할 때 직접 확정합니다. |
| 읽기 전용에서 에이전트가 시작되지 않음 | 읽기 전용은 Codex, Claude Code, Gemini CLI, Qwen Code, CodeBuddy, Copilot에서만 됩니다. | 실행 권한을 **기본**으로 바꾸거나 위 에이전트를 씁니다. |
| 에이전트가 만든 파일이 파일 목록에 늦게 보임 | 0.11.7-preview.5 이하 버전의 문제입니다. | 0.11.7-preview.6 이상으로 업데이트합니다. |

그래도 안 되면 [GitHub 이슈](https://github.com/jhy0285/monofield/issues)에 증상과 화면을 남겨 주세요.
