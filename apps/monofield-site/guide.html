USER GUIDE · 0.11.7-preview.9

개발자는 따라 하고,PM·팀장은 결과만 읽는 사용 가이드

MonoField는 Spring 코드에서 SI 인터페이스 명세서(Excel)를 만들고, 코드가 바뀌면 어떤 API가 어떻게 바뀌었는지, 그 변경이 호출하는 쪽을 깨는지를 알려 주는 Windows 데스크톱 도구입니다. 화면명세서(PPTX)도 만듭니다. 이 가이드는 두 사람을 위해 썼습니다. 개발자는 2장을 순서대로 따라 하면 되고, 결과를 받아 보는 PM·팀장은 1장과 3장만 읽으면 됩니다.

이 가이드의 본문은 한국어입니다. 화면 이름은 앱의 한국어 표시를 따릅니다.

01

한눈에 보기

MonoField는 코드를 PC 밖으로 보내지 않고, 0.3초에, 매번 같은 결과로, 일반 AI와 비슷한 정확도의 명세서와 변경 분류를 만듭니다. 명세서 스캐너와 변경 분석이 AI 모델을 부르지 않는 프로그램이기 때문입니다. Codex·Claude Code 같은 AI는 이름 보충이나 수정안 작성처럼 채팅으로 시키는 일에만 씁니다(5장).

검증한 숫자

가상의 교통 결제 시스템(Spring Boot, API 68개, Java 파일 213개)을 만들어 같은 코드를 MonoField와 일반 Claude Code에 주고, 미리 만든 정답표와 비교했습니다.

항목MonoField일반 Claude Code (6회)
API 경로68/6868/68
요청 필드 / 응답 필드100% / 98% (생성일 같은 감사 필드는 기본으로 뺌)100% / 95~100%
인증 필요 여부68/6868/68
코드 변경으로 바뀐 항목 찾기152/152, 잘못 찾은 것 096~100%
호환성 분류 (깨짐 · 확인 필요 · 추가)100% 일치94~100%, 실행마다 다름
영향받은 API 표시34/34, 불필요한 표시 0측정하지 않음
걸린 시간 · 모델 비용0.3초 · 0원4~8분 · 약 $1~1.4

방법과 원자료는 실험 결과에 있습니다.

아직 못 하는 것

  • 열거값 추가, 기본값 변경, 권한 범위(scope) 변경은 명세서에 그 칸이 없어 찾지 못합니다. 일반 AI는 실험의 4건을 모두 찾았습니다. 코드 리뷰나 릴리스 노트로 확인하세요.
  • Spring(Java) 코드를 기준으로 다듬었습니다. Kotlin 컨트롤러는 읽지 않습니다. Django, Express, FastAPI, Go, NestJS, OpenAPI용 스캐너도 명세서는 만들지만, 변경 분석에서는 바뀐 파일을 쓰는 API를 넓게 표시합니다.
  • 서블릿 필터, 인터셉터, DB에 저장한 접근 규칙은 읽지 않습니다. 그런 API의 인증 칸은 "확인 필요"로 남고 사람이 정합니다.
  • 숫자는 가상 시스템에서 한 번 잰 결과입니다. 실제 프로젝트에서는 처음 1~2주 동안 모듈 하나로 확인해 보세요.

02

개발자: 처음부터 따라 하기

예제 프로젝트로 약 20분 걸립니다. 단계마다 확인 문장대로 보이면 다음으로 넘어가세요.

준비물

준비물확인 방법없으면
Windows 10/11 (64비트)—데스크톱 앱은 지금 Windows만 지원합니다.
Codex CLI 또는 Claude Code CLI명령 프롬프트에서 codex --version 또는 claude --version공식 안내대로 설치하고 로그인까지 합니다. 둘 중 하나면 됩니다.
Python 3python --versionpython.org에서 설치하면서 Add python.exe to PATH를 체크합니다. 스캐너와 변경 분석이 Python으로 돕니다.
Gitgit --versiongit-scm.com에서 설치합니다. 변경을 비교하는 기준점에 씁니다.

1단계. 설치하고 연결 확인 (3분)

  1. 사이트에서 Windows Preview 다운로드를 눌러 설치합니다. "Windows의 PC 보호" 창이 뜨면 추가 정보 → 실행을 누릅니다(아직 코드 서명이 없습니다).
  2. MonoField를 켜면 화면 안내가 시작됩니다. 강조된 곳을 따라 눌러 보세요.
  3. 설정(톱니바퀴) → 실행 모드에서 로컬 CLI를 고릅니다. 확인: 목록에 Codex 또는 Claude Code가 보입니다.
  4. 설정 → 실행 권한은 기본으로 둡니다. 읽기 전용이면 명세서 파일을 만들 수 없습니다.

2단계. 예제 프로젝트 준비 (2분)

  1. 예제 프로젝트(legacy-order.zip)를 받아 압축을 풉니다. 회원·주문 API가 있는 작은 Spring 프로젝트입니다.
  2. legacy-order 폴더에서 명령 프롬프트를 열고 아래 세 줄을 입력합니다. 지금 코드를 기준점으로 저장하는 단계입니다.
git init
git add -A
git commit -m "baseline"

Please tell me who you are 오류가 나면 git config --global user.name "이름"과 git config --global user.email "메일"을 한 번 실행하고 다시 커밋합니다.

3단계. 명세서 만들기 (5분)

  1. MonoField 홈에서 작업 폴더 선택을 눌러 legacy-order 폴더를 고릅니다.
  2. 입력창 아래 결과 형식 선택에서 인터페이스 명세서를 고르고 이렇게 보냅니다: "선택한 Spring 프로젝트의 Controller를 스캔해서 인터페이스 명세서 Excel을 만들어 줘"
  3. 오른쪽 질문 탭에서 작성 방식 → 코드베이스에서 생성, 한글-영어 매핑 사전 → 사전 업로드 → 예제의 docs/term-dictionary.csv를 고르고, 나머지는 그대로 두고 제출합니다.
  4. 확인: 프로젝트에 …interface-spec.json 파일이 생기고 명세서 편집기가 열립니다. 내보내기를 누르면 Excel이 만들어집니다.
  5. 명세서 파일도 커밋해 둡니다(git add -A, git commit -m "명세서 v1.0"). 팀과 버전을 맞추기 쉬워집니다.

이 방법은 Codex·Claude Code가 스캐너를 실행하면서 코드를 읽으므로 코드 일부가 그 AI 회사로 전송됩니다. 외부 AI가 금지된 현장은 이 장 끝의 외부 AI 없이 쓰기를 따르세요.

4단계. 사람이 채울 칸 확인 (3분)

칸왜 사람이 보나요
인터페이스 ID (예: IF-ORD-001)코드에 없는 정보라 팀 규칙대로 정합니다.
업무명메서드 위 한글 주석(/** 주문 등록 */)이 있으면 그 문장을 씁니다. 없으면 비어 있습니다.
한글 필드명용어 사전 → 필드 주석 → 영문 분리 순서로 정합니다. member Id처럼 남으면 사전에 추가하고 다시 만듭니다.
인증 "확인 필요"Java·XML 보안 설정과 애너테이션으로 정합니다. 필터·인터셉터·DB 규칙으로만 막는 API는 직접 정합니다.

5단계. 코드를 바꾸고 변경 분석 (3분)

  1. 채팅에 보냅니다: "주문 등록에 배송 요청 사항(deliveryMemo)을 추가하고 주문 취소 API를 만들어 줘". 변경사항 탭에서 바뀐 줄을 확인합니다.
  2. 명세서 편집기에서 Git 변경 분석을 누릅니다. AI를 부르지 않고, PC 안에서 기준 시점의 코드와 지금 코드를 스캐너로 다시 읽어 비교합니다.
  3. 확인: 맨 위에 "기준 시점과 지금의 코드를 스캐너로 다시 읽어 비교했습니다"가 보입니다. 에이전트가 요청대로 고쳤다면 영향받은 항목에 주문 등록 하나, 호출자 호환성에 "추가 변경", 문서에 없는 새 인터페이스에 POST /api/v1/orders/{orderId}/cancel이 나옵니다.

변경을 먼저 커밋해도 됩니다. 명세서를 만들 때 Java·XML 파일이 모두 커밋되어 있었다면 스캐너가 그 커밋을 기록해 두고, 나중에 그 커밋과 비교합니다.

6단계. 명세서에 반영하고 내보내기 (4분)

  1. AI 갱신 요청 작성 → 전송. AI가 바뀐 인터페이스만 고친 수정안을 만듭니다.
  2. AI 제안 검토에서 현재 문서와 AI 제안을 나란히 보고 검토한 제안 적용 → 저장합니다.
  3. 내보내기로 새 버전 Excel을 만들고, 필요하면 OpenAPI 내보내기로 API 게이트웨이·Mock용 OpenAPI 3.1 파일도 받습니다.
  4. 검토하는 사이에 원본 명세서가 바뀌면 적용이 거부됩니다. Git 변경 분석부터 다시 하면 됩니다.

7단계. PM·팀장에게 보내기

  • 새 버전 Excel 파일.
  • Git 변경 분석 결과: 화면 캡처, 또는 명령줄의 monofield docs impact --project <id> --input <명세서.json> 출력.
  • 사람이 정해야 할 칸 목록(인터페이스 ID, 인증 "확인 필요").

외부 AI 없이 쓰기

고객사 규정으로 외부 AI를 쓸 수 없으면 스캐너를 직접 실행합니다. 스캐너는 Python 표준 라이브러리만 쓰고 네트워크에 접속하지 않습니다.

  1. GitHub 저장소에서 Code → Download ZIP으로 받아 압축을 풉니다. 스캐너는 plugins/_official/interface-spec/scripts/scan_spring.py 파일입니다.
  2. 명령 프롬프트에서 아래처럼 실행합니다. <...>는 내 환경의 경로로 바꿉니다.
python <압축 푼 폴더>\plugins\_official\interface-spec\scripts\scan_spring.py ^
  --codebase-path <프로젝트 폴더> ^
  --name-dict <프로젝트 폴더>\docs\term-dictionary.csv ^
  --out <프로젝트 폴더>\docs\api.interface-spec.json
  1. MonoField에서 작업 폴더 선택으로 그 프로젝트를 열고 만들어진 JSON 파일을 엽니다. 편집, 내보내기(Excel), OpenAPI 내보내기, Git 변경 분석은 AI 없이 동작합니다.
  2. 변경 반영은 편집기에서 직접 고치거나 스캐너를 다시 실행해 새로 만듭니다(새로 만들면 사람이 채운 칸을 다시 채워야 합니다). AI 갱신 요청 작성은 쓰지 않습니다.

03

PM·팀장: 결과 읽는 법

직접 실행할 필요는 없습니다. 개발자가 보내 준 Excel과 변경 분석 결과를 아래 순서로 읽으세요.

받는 것

받는 것들어 있는 것
인터페이스 명세서 Excel문서표지, 인터페이스 목록, API마다 한 시트(요청·응답 필드, 타입, 필수 여부, 길이), 문서 근거(각 항목이 어느 파일 몇째 줄에서 왔는지)
변경 분석 결과영향받은 인터페이스, 호출자 호환성(호환성 깨짐 · 확인 필요 · 추가 변경), 명세서에 없는 새 인터페이스

변경 분석 읽는 순서

  1. 맨 위 문장부터 봅니다. "기준 시점과 지금의 코드를 스캐너로 다시 읽어 비교했습니다"면 표시된 API는 계약이 실제로 바뀐 것뿐입니다. "바뀐 파일을 근거로 쓰는 인터페이스를 모두 표시했습니다"면 넓게 표시한 것이니, 실제로 바뀐 API가 무엇인지 개발자에게 물어보세요. 정밀 비교를 못 한 이유는 그 아래에 나옵니다.
  2. 호환성 깨짐이 0이 아니면 가장 먼저 챙깁니다. 그 API를 부르는 쪽(화면, 대외기관, 다른 팀)에 알리고 배포 순서와 일정을 맞춥니다.
  3. 확인 필요는 의도를 개발자에게 확인합니다.
  4. 추가 변경과 새 인터페이스는 기존 호출에 영향이 없습니다. 명세서와 테스트 계획에 넣으면 됩니다.
  5. Excel에서 비어 있거나 "확인 필요"인 칸(인터페이스 ID, 업무명, 인증 여부)은 담당자를 정합니다. MonoField는 근거가 없으면 추측해서 채우지 않습니다.

호환성 세 단계

표시뜻이런 변경할 일
호환성 깨짐지금 호출하는 쪽이 고장 날 수 있음응답 필드 삭제, 필수 요청 필드 추가, 요청 필드가 필수로 변경, 필드 타입 변경, 최대 길이 축소, 인터페이스 삭제, 인증 필요로 변경호출하는 쪽에 공지, 배포 순서 조율
확인 필요상황에 따라 영향이 다름요청 필드 삭제, 필수 여부를 알 수 없는 요청 필드 추가, 응답 필드가 선택으로 변경, 인증 불필요로 변경개발자에게 의도 확인
추가 변경기존 호출에 영향 없음선택 요청 필드 추가, 응답 필드 추가, 요청 필드가 선택으로 변경, 새 인터페이스명세서·테스트에 반영

개발자에게 물어볼 것

  • "호환성 깨짐 API를 부르는 곳은 어디고, 언제 배포하나요?"
  • "이번 변경에서 상태 코드 같은 열거값, 기본값, 권한 범위가 바뀐 곳이 있나요?" (MonoField가 찾지 못하는 변경입니다)
  • "인증 '확인 필요' 칸은 누가 언제 확정하나요?"
  • "정밀 비교를 못 했다고 나왔는데, 실제로 바뀐 API는 몇 개인가요?"

믿어도 되는 것과 사람이 볼 것

믿어도 되는 것사람이 볼 것
같은 코드면 언제 돌려도 같은 결과열거값·기본값·권한 범위 변경
경로·필드·필수 여부·타입과 그 근거(파일과 줄)인터페이스 ID, 업무명, 비어 있는 한글 필드명
호환성 단계를 나누는 규칙필터·인터셉터·DB 규칙으로 정하는 인증
"다시 읽어 비교했습니다"일 때의 영향받은 API 목록Kotlin 등 Spring(Java)이 아닌 코드의 변경

  • AI 요금은 연결한 Codex·Claude Code 계정 기준으로 나갑니다. MonoField 자체는 무료(Apache-2.0)입니다.

  • 설치본은 아직 코드 서명이 없습니다. 내려받은 파일은 릴리스의 SHA256SUMS.txt로 확인할 수 있습니다. 프리뷰는 안정 버전과 따로 설치됩니다.

07

레퍼런스 보드와 내장 REA

레퍼런스 보드: 마음에 든 화면의 패턴을 내 프로젝트에

  1. 작업공간의 + (새 탭) → 새 브라우저를 엽니다.
  2. 참고할 사이트를 열고 주소창 오른쪽 레퍼런스로 담기를 누릅니다. 메모와 가져올 것(화면 구조·흐름·필드 구성·상호작용)을 고르고 담기를 누릅니다.
  3. 새 브라우저 탭 시작 화면의 담은 레퍼런스에서 카드를 체크하고 선택한 n개 프로젝트에 넣기 → 넣을 위치와 요청을 적고 입력창에 넣기를 누릅니다.
  4. 흐름이 중요하면 카드의 REA로 흐름 기록으로 단계(버튼 누르기·입력·기다리기)를 기록하고, 화면을 만든 뒤 우리 화면과 비교로 단계마다 나란히 비교합니다.

패턴만 가져옵니다. 문구·이미지·로고·브랜드 색·글꼴은 복사하지 않습니다. 로그인이나 봇 차단은 대신 통과하지 않고, 비밀번호·인증번호·카드번호 칸에는 입력 단계를 만들 수 없습니다. 자세한 내용은 레퍼런스 보드를 보세요.

REA는 MonoField에 들어 있습니다

  • REA(rea-agents 6.7.0)는 MonoField에 들어 있습니다. Node.js 설치나 npx 내려받기가 필요 없습니다.
  • 대화에서 AI가 REA 쓰기는 기본으로 켜져 있습니다. Claude Code, Codex, OpenCode와 지원 ACP 에이전트가 별도 설정 없이 REA 도구를 받습니다. 새 대화부터 적용됩니다.
  • 끄거나 다시 켜려면 설정 → 외부 MCP 맨 위의 REA 설치·연결 점검에서 스위치를 누르거나 monofield rea disable / monofield rea enable을 씁니다.
  • 브라우저 기록에는 PC에 설치된 Chrome·Edge·Chromium이 필요합니다. BYOK(API 키)만 연결한 대화에는 REA 같은 도구가 주어지지 않습니다.

막혔을 때

증상해결
실행 모드에 Codex/Claude가 안 보임명령 프롬프트에서 codex --version(또는 claude --version)이 되는지 확인하고, 로그인한 뒤 MonoField를 다시 켭니다.
명세서를 만들 수 없다고 나옴실행 권한이 읽기 전용입니다. 기본으로 바꿉니다.
"현재 작업 폴더는 Git 저장소가 아닙니다"폴더에서 git init, git add -A, git commit -m "baseline"을 실행합니다.
변경 분석에 "정밀 비교를 하지 못한 이유: Python 3 was not found"Python 3을 설치하면서 Add python.exe to PATH를 체크하고 MonoField를 다시 켭니다.
변경 분석에 "정밀 비교를 하지 못한 이유: … not made by a scanner …"직접 만들었거나 Spring이 아닌 스캐너로 만든 명세서입니다. 바뀐 파일 기준으로 넓게 표시한 결과이니 표시된 API를 하나씩 확인합니다.
코드를 바꿨는데 변경 분석에 아무것도 안 나옴명세서를 만들 때 커밋하지 않은 Java 파일이 있었고, 그 뒤 변경을 커밋했을 수 있습니다. 그때는 지금의 커밋과 비교합니다. 명세서를 만들기 전에 코드를 커밋해 두세요.
인증이 "확인 필요"로 남음오류가 아닙니다. 필터, DB 규칙, hasIpAddress처럼 풀 수 없는 규칙입니다. 검토할 때 직접 정합니다.
한글 필드명이 member Id처럼 나옴용어 사전에 추가하고 다시 만듭니다.
AI가 REA 도구를 못 찾음설정 → 외부 MCP → REA 설치·연결 점검에서 대화에서 AI가 REA 쓰기가 켜져 있는지 보고 새 대화를 시작합니다.
레퍼런스로 담기 때 화면 캡처가 없음데스크톱 앱에서만 캡처와 구조 요약을 찍습니다. 웹 브라우저로 쓰면 주소와 메모만 담깁니다.

그래도 안 되면 GitHub 이슈에 증상과 화면을 남겨 주세요.

명령줄(CLI)

화면에서 하는 일은 명령줄로도 할 수 있습니다. 두 쪽이 같은 로컬 데몬의 /api/*를 부르며, 명령마다 --help로 사용법을 볼 수 있고 대부분 --json 출력을 지원합니다.

명령하는 일
python scan_spring.py --codebase-path <폴더> --out <명세서.json>AI 없이 Spring 코드에서 명세서 JSON 만들기
monofield docs render-interface-spec --input <명세서.json>명세서 JSON을 Excel로
monofield docs impact --project <id> --input <명세서.json>Git 변경 분석(다시 읽어 비교, 호출자 호환성, 새 인터페이스)
monofield docs export-openapi --input <명세서.json>OpenAPI 3.1로 내보내기
monofield refs …레퍼런스 보드(담기·메모·적용·흐름 기록·비교)
monofield rea status|enable|disable|doctor내장 REA 설정과 점검
monofield permissions [show|set <level>]실행 권한 확인·변경
