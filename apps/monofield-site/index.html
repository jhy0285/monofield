04 / WAYS OF WORKING

Start with the work, not the tool.

Choose software development or documents / design when you create a project. Ask and Docs modes remain available inside either project whenever the task changes.

A

SOFTWARE DEVELOPMENT

Read. Change. Run. Verify.

  • Working folder becomes the actual execution root
  • Side-by-side diff, build status, and IDE handoff
  • In-app browser with DOM marks and automated checks
  • Governed database reads and approval-based writes
B

DOCUMENT & DESIGN

Collect. Compose. Review. Export.

  • Interface and screen specifications grounded in evidence
  • Decks, responsive web, prototypes, wireframes, and media
  • Reusable brand systems, files, glossaries, and workflows
  • Preview, comments, visual marks, validation, and export

05 / ONE CONTINUOUS LOOP

From context to delivery.

  1. 01

    Connect

    Choose a working folder. Attach only the browser, data, files, and rules this project needs.

  2. 02

    Work

    Use the selected CLI runtime to inspect, implement, build, compose, or export from the same project root.

  3. 03

    Verify

    Review diffs and artifacts. Validate the running UI and interactions in the approved browser tab.

  4. 04

    Deliver

    Keep the code, evidence, document, and export attached to the project—not scattered across separate tools.

06 / LOCAL-FIRST

Your workspace stays yours.

MonoField runs as an open-source desktop app. Project files stay in the folder you choose. Stored credentials remain in the encrypted desktop vault and are not inserted into model prompts.

When you use an external model, the prompt and the context you explicitly send are processed by that provider under its policy. Local-first does not mean external providers receive nothing.
